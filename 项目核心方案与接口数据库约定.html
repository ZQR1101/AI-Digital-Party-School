一、文档目的

本文件用于统一移动端、管理后台和后端的开发目标、业务流程、数据结构及接口规则。团队成员在开发前共同确认本文件；后续如需调整字段或接口，应同步更新文档并通知全组。

二、系统整体结构

系统由"移动端前端 + 管理后台前端 + 统一后端 + MySQL 数据库 + AI 大模型能力"构成。

模块主要职责
移动端党员登录、查看学习任务、学习文章或视频、答题考试、查看个人学习报告。
管理后台组织架构、人员、学习内容、学习任务、题库、试卷和统计数据管理。
后端登录鉴权、业务逻辑、数据库访问、统一接口、统计计算、文件服务和 AI 能力调用。
AI 能力基于学习记录和成绩生成个人学习报告，输出评分、评语和改进建议。

三、最小可演示核心流程

管理员登录管理后台
→ 发布学习内容和学习任务
→ 党员登录移动端
→ 查看任务并完成文章/视频学习或答题
→ 后端保存学习记录和成绩
→ 后台查看完成率、学习时长和平均分
→ 党员查看 AI 生成的个人学习报告

开发优先级：先跑通上述闭环（对应 P0 接口），再逐步补充题库、推荐、自然语言查询等扩展功能。不要等全部功能完成后才开始联调。

四、用户角色与权限

角色使用端主要权限
党员移动端查看本人任务、学习内容、参加考试、查看个人成绩和学习报告。
支部书记管理后台管理本组织及下级组织的人员和任务，查看权限范围内的统计数据。
系统管理员管理后台管理全部组织、人员、内容、题库、试卷和全局统计数据。

五、多级党组织架构约定

组织架构不固定为"党委—支部"两级，而是采用通用树形结构，可按实际情况配置任意层级。

学校党委
├─ 信息工程学院党委
│  ├─ 软件工程系党总支
│  │  ├─ 学生第一党支部
│  │  │  ├─ 第一党小组
│  │  │  └─ 第二党小组
│  │  └─ 教师党支部
│  └─ 计算机系党总支
└─ 机关党委
   └─ 行政第一党支部

组织管理页面采用树形展示。发布任务时，可选择指定组织，并支持下发至该组织及其全部下级组织的成员。

六、数据库核心表约定

表名核心字段说明
usersid, username, password, realName, role, organizationId用户账号、姓名、角色和所属组织。
organizationsid, name, type, parentId, leaderUserId多级组织树；顶级组织的 parentId 为 null。
contentsid, title, type, coverUrl, bodyOrVideoUrl, status文章或视频内容；type 可为 article 或 video。
learning_tasksid, title, contentId, organizationId, deadline, status后台发布的学习任务。
learning_recordsid, userId, taskId, studySeconds, completedAt, status党员学习时长和完成状态。
questionsid, type, title, options, answer, analysis单选、多选、判断等题库信息。
exam_recordsid, userId, taskId, score, submittedAt党员考试或测验的成绩记录。

组织类型统一约定（camelCase）：committee（党委）、generalBranch（党总支）、branch（党支部）、group（党小组）。

🔧 v1.1 修正：general_branch 已改为 generalBranch，与通用规则中的 camelCase 命名保持一致。

七、统一接口约定

1. 通用规则

项目约定
接口前缀/api
数据格式请求和响应均使用 JSON；文件上传接口除外。
字段命名统一使用 camelCase，例如 taskId、userId、organizationId。
时间格式YYYY-MM-DD HH:mm:ss，例如 2026-07-23 15:30:00。
认证方式登录成功后获取 token；后续请求在 Authorization: Bearer <token> 中携带。
成功响应{ "code": 0, "message": "success", "data": {} }
常用错误码400：参数错误；401：未登录或登录过期；403：无权限；404：资源不存在；500：服务器异常。
分页约定请求参数 page（从 1 开始）、pageSize（默认 10）；响应返回 total（总数）和 list（当前页数据）。
🔧 v1.1 新增：补充了分页约定的显式说明，前后端按统一规则对接分页接口。

2. 核心接口清单

优先级方法地址用途使用端
P0POST/api/auth/login用户登录，返回 token 与用户信息。移动端、管理后台
P0GET/api/users/me获取当前登录用户信息与角色。移动端、管理后台
P0GET/api/tasks/my获取当前党员的学习任务列表。移动端
P0GET/api/tasks/{taskId}获取任务和学习内容详情。移动端
P0POST/api/learning-records提交学习时长、完成状态。移动端
P0POST/api/exam-records提交答案并返回成绩或错题分析。移动端
P0POST/api/admin/contents新增或发布文章、视频内容。管理后台
P0POST/api/admin/tasks向指定组织发布学习任务。管理后台
P1GET/api/reports/me获取 AI 个人学习报告（评分+评语+建议）。移动端
P1GET/api/admin/statistics查看学习时长、完成率、平均分等统计数据。管理后台

3. 管理后台 CRUD 扩展接口（P1 / P2）

以下接口在一期闭环跑通后逐步补充，前端可先用 P0 接口 + Mock 数据并行开发。

优先级方法地址用途
P1GET/api/admin/organizations获取组织树列表。
P1POST/api/admin/organizations新增组织节点。
P1PUT/api/admin/organizations/{id}编辑组织信息。
P1DELETE/api/admin/organizations/{id}删除组织节点（需校验无下级组织和人员）。
P1GET/api/admin/users分页查询人员列表，支持按组织筛选。
P1POST/api/admin/users新增党员账号。
P1PUT/api/admin/users/{id}编辑人员信息。
P2PUT/api/admin/contents/{id}编辑已发布的内容。
P2DELETE/api/admin/contents/{id}下架或删除内容。
P2PUT/api/admin/tasks/{id}修改已发布任务。
P2DELETE/api/admin/tasks/{id}撤销或删除任务。
P1GET/api/admin/questions分页查询题库。
P1POST/api/admin/questions新增题目。
P2PUT/api/admin/questions/{id}编辑题目。
P2DELETE/api/admin/questions/{id}删除题目。

4. 接口示例：获取我的学习任务

GET /api/tasks/my?page=1&pageSize=10&status=unfinished
Authorization: Bearer <token>
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 1,
    "list": [
      {
        "taskId": 101,
        "title": "学习党的二十大精神",
        "contentType": "article",
        "deadline": "2026-08-01 23:59:59",
        "progress": 60,
        "status": "inProgress"
      }
    ]
  }
}

移动端根据 list 展示任务；后端按同名字段返回数据；后台发布任务时也使用同一套任务字段。

5. 接口示例：提交学习记录

POST /api/learning-records
Content-Type: application/json

{
  "taskId": 101,
  "studySeconds": 900,
  "completed": true
}

后端根据 taskId 即可关联到对应学习内容，无需前端额外传递 contentId。字段名与数据库 learning_records 表的 studySeconds 保持一致。

🔧 v1.1 修正：去掉了多余字段 contentId，并将 studyDurationSeconds 统一为 studySeconds，与数据库字段名一致。

八、团队开发分工与协作节奏

成员负责内容最先完成的内容
成员 A移动端：登录、任务、学习、答题、个人报告。登录页、任务列表、内容详情页；可先用 Mock 数据开发。
成员 B管理后台：组织、内容、任务、统计。登录页、内容发布、任务发布、统计页面；可先用 Mock 数据开发。
成员 C后端：数据库、权限、接口、统计和 AI 调用。数据库建表、登录、任务列表、提交学习记录、统计接口。

协作节奏：第一天共同确认本文件；之后并行开发；每天或每两天联调一次。后端每完成一个核心接口，两个前端即切换该接口进行联调，优先验证 P0 闭环。

九、移动端功能要求

以下移动端功能要求来自赛题任务清单：

1. 学习内容观看

移动端支持党员观看学习（仅能查看【学习任务发布】模块指定的内容和公共内容）。

2. 测验答题

移动端进行测验。

3. 个性化学习推荐

在移动端基于党员的学习历史、测验错题、薄弱知识点，推荐公共内容中的相关内容。

4. AI综合评价报告

在移动端中综合学习频率、测验分数、试卷成绩等维度，生成个人学习报告（评分+评语+改进建议）。

十、后台管理功能要求

以下后台管理功能要求来自赛题任务清单：

1. 组织架构管理

管理后台支持创建/编辑/删除党支部，支持多级结构（至少2级：党委/总支→支部），支持查看各支部统计数据。

2. 人员管理

管理后台支持党员信息增删改查、批量导入（Excel/CSV）、角色分配（党员/支部书记/系统管理员）、按姓名/支部/角色搜索。

3. 学习内容管理

管理后台支持文章、视频的发布、编辑、删除、分类，可设置标签明确某个文章或视频为公共内容。

4. 学习任务发布

以支部为单位派发学习任务，明确支部内党员需要学习的内容。

5. 题库管理

管理后台支持单选、多选、判断三种题型，支持题目分类和批量导入。

6. 试卷功能

管理后台支持创建试卷。

7. 测验发布

管理后台根据试卷发布测验。

8. 数据统计

管理后台支持学习时长、完成率、测验平均分、考试通过率等可视化展示，支持按支部筛选。

9. 自然语言组织数据查询

在管理后台中管理员输入如"今年三支部学习完成率"，系统返回文本+图表。

十一、后端功能要求

本命题要求参赛团队开发一个包含管理后台（服务于组织管理者）和移动端（服务于党员个人）的党校学习双端系统，系统需整合AI能力。后端为上述移动端功能要求和后台管理功能要求提供统一的接口服务、数据存储、业务逻辑处理、权限鉴权、统计分析及AI大模型能力调用。后端框架：不限。

十二、版本管理与联调要求

所有成员使用同一 Git 仓库或统一代码管理方式；不得提交数据库密码、API Key 等敏感信息。接口字段、状态值和数据库字段如需修改，必须先在群内确认并同步更新本文件。每次联调优先验证"后台发布任务—移动端学习—后端记录—后台统计—个人报告"的完整闭环。
