项目启动会议

四端开发：移动端 · 网页端 · 后端 · AI功能设计

参考文档：《基于AI的数智党校学习系统——项目详细方案》 ｜ 会议目标：确认技术选型、明确分工、制定第一轮迭代计划

一、项目整体回顾（5分钟）

要点说明
项目定位党建学习与组织管理数字化平台——面向党员学习者和组织管理者
核心闭环管理员发布任务 → 党员移动端学习/答题 → 后台统计分析 → AI 生成个人学习报告
目标用户党员（移动端）、支部书记（管理后台）、系统管理员（管理后台）
技术架构移动端（小程序/UniApp）+ 网页后台（Vue + Element Plus）+ 后端（Spring Boot / Node.js）+ MySQL + 大模型API

二、四个开发部分讨论

📱 移动端（党员端）

  • 技术选型：微信小程序 or UniApp？
  • 核心页面：登录首页、学习任务列表、文章/视频学习、测验考试、AI报告卡片、个人中心
  • 关键交互：学习时长记录、答题提交与即时反馈、任务状态切换
  • 待确认：UI风格（红色党建主题？）、是否需要离线缓存
产出：技术选型结论 + 页面清单

🖥 网页端（管理后台）

  • 技术选型：Vue + Element Plus（方案推荐）
  • 核心页面：组织树管理、人员管理、内容发布、任务下发、题库组卷、数据统计看板
  • 关键功能：多级组织树形控件、任务指定组织下发、可视化统计图表
  • 待确认：图表库（ECharts？）、AI自然语言查询是否一期做？
产出：组件/图表库选型 + 页面优先级排序

⚙ 后端服务

  • 技术选型：Spring Boot / Node.js / Python？
  • 数据库：MySQL，核心表7张（users, organizations, contents, learning_tasks, learning_records, questions, exam_records）
  • 接口规范：/api 前缀、JSON格式、Bearer Token、统一响应体
  • 待确认：开发框架、接口文档工具（Swagger？）、文件/视频存储方案
产出：技术栈确定 + DDL脚本 + 接口文档初稿

🤖 AI 功能设计

  • 一期重点：AI 个人学习报告（完成率 + 学习时长 + 成绩 + 错题 → 评分 + 评语 + 建议）
  • 实现策略：后端统一调用大模型API，前端仅展示结果
  • 异常处理：超时/格式异常时降级为预设文案
  • 待确认：选哪个大模型（文心/通义/DeepSeek？）、API成本、扩展功能范围
产出：AI功能范围 + Prompt模板初稿

三、并行开发协调机制

协调事项说明
接口先行后端先定接口文档 → 移动端和网页端可按文档并行 Mock 开发，互不阻塞
数据规范统一字段命名统一驼峰（taskId、userId、organizationId），时间格式 YYYY-MM-DD HH:mm:ss
联调节奏后端完成一个接口即与两端联调一个接口，不要等全部完成再联调，早发现问题早解决
代码仓库统一 Git 仓库结构（建议 mono-repo，按 client/admin/server/ai 分目录）
每日同步建议每天简短同步进度和阻塞点，使用共享文档跟踪接口完成状态

四、分工建议（参考方案，需现场确认）

角色负责部分第一阶段核心交付物
队长 / 统筹需求拆解、原型流程、进度协调、文档与答辩需求清单、原型图/流程图、会议纪要、进度跟踪表
成员A移动端开发登录首页、任务列表、内容学习页面、考试页面
成员B网页后台开发组织管理、人员管理、内容发布、任务下发页面
成员C后端开发数据库DDL脚本、核心接口实现、接口文档（Swagger）
成员DAI功能 + 联调测试Prompt模板、AI报告接口、全流程联调、演示数据准备
⚠ 重要提醒：方案文档中给出的分工为五人制（1队长 + 2前端 + 1后端 + 1AI/测试），实际需要根据团队人数调整。若人数不足，可合并网页端与AI测试角色，或由队长兼顾部分开发。

五、核心接口清单（后端优先实现）

方法接口地址说明优先级
POST/api/auth/login用户登录，返回 token 和用户基本信息P0
GET/api/tasks/my获取当前党员的学习任务列表P0
GET/api/tasks/{taskId}获取任务及学习内容详情P0
POST/api/learning-records提交学习时长和任务完成状态P0
POST/api/exam-records提交答案，返回成绩和错题分析P0
GET/api/reports/me获取 AI 个人学习报告P1
POST/api/admin/tasks后台向指定组织发布学习任务P0
GET/api/admin/statistics后台获取学习统计数据P1

六、第一阶段迭代计划（建议4周）

第1周
基础搭建——技术选型敲定、数据库建表完成、接口文档初版发布、各端搭建项目骨架并跑通登录接口
第2-3周
核心开发——移动端/网页端核心页面开发、后端核心接口全部完成并交付、AI模块联调通过
第4周
集成联调——全流程联调（发布→学习→答题→统计→AI报告）、准备演示数据与测试账号、演示彩排

七、待决议题清单（会议中逐项确认）

  • 移动端用微信小程序还是 UniApp？需考虑比赛要求和团队技术储备
  • 后端框架选 Spring Boot 还是 Node.js？需统一意见
  • AI 大模型选哪家？（文心一言 / 通义千问 / DeepSeek / 其他）
  • 文件/视频存储方案？（本地存储 / 阿里云OSS / 其他云存储）
  • 各端代码仓库结构如何组织？（mono-repo 还是多仓库）
  • 是否需要 UI 设计稿，还是直接使用组件库默认样式？
  • 团队实际人数是否与方案中五人对齐？如何调整分工？
  • AI 扩展功能（个性化推荐、自然语言数据查询）是否纳入一期？
