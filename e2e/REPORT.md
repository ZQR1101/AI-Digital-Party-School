| 链路 | 用例 | 断言层次 |

## 二、发现并修复的问题

1. **P0 书记端无法发布任务（真实业务缺陷，RBAC 配置错误 + 组织树过滤缺陷，两处根因）**
   - 根因一：`/api/admin/organizations` 与 `/api/admin/contents` 整个路由器 `requireAdmin`，而任务管理页（书记可用）的表单需要调这两个接口加载选项；且 organizations 的三个写接口（POST/PUT/DELETE）此前未显式挂 `requireAdmin`（依赖过路由级配置，语义不明确）。
   - 根因二（E2E 首轮实跑后经 trace 定位）：`filterTree` 按"节点 ID 必须在允许集合内"过滤，但书记可管理组织（学生第一党支部）是深层子节点，其祖先不在允许集合中，导致整棵树被剪成 `data:[]`——书记即使拿到 200 响应，组织下拉仍为"No data"，任务依旧无法创建。首轮修复只开放了 GET，并未真正打通。
   - 修复（最小根因）：organizations 的 GET 开放给 manager，三个写接口逐个显式 `requireAdmin`；contents 的 GET 开放给 manager（仅返回已发布内容）；`filterTree` 重写为"命中节点保留整棵子树，未命中节点若后代命中则保留祖先路径"，提取为 `server/src/utils/orgTreeFilter.js` 并新增 4 项单元测试；`security-hardening.test.js` 结构断言同步强化（组织/内容写操作必须保留 requireAdmin）。server 回归 206/206。

2. **文档与代码不一致**：DEPLOY.md 的 `RERANKER_API_URL` 示例为百炼旧原生端点；按 `server/.env.example` 与 `reranker.js` 实际支持协议修正为 `https://dashscope.aliyuncs.com/compatible-api/v1/reranks`。

3. **观察项（未在本轮处理）**：管理后台布局（AdminLayout.vue）侧边栏/顶栏的用户名与角色为硬编码"系统管理员"，书记登录后显示不变，属展示层既有问题，与鉴权无关，留待后续 UI 迭代。

## 四、工程与 CI

- 工程：`e2e/`（Playwright + mysql2 直连断言），全局 setup 自动拉起隔离栈并种子数据、teardown 销毁并断言无遗留容器/卷；运行时产物（`.runtime/`、`test-results/`、`playwright-report/`）不入库。
- 稳定性约定：全部关键控件补 `data-testid`（两端 15 处）、无固定 sleep（进度用 `toHaveText` 轮询、落库用 `expect.poll` 轮询 DB）、失败自动保存截图/trace（输出目录可重定向，不进仓库）。
- CI（如实区分）：
  - 主流水线 `ci.yml` 的 `e2e-smoke` job：每次 push 运行 `--grep @smoke` 的 **3 项冒烟用例**，控时约 5 分钟；
  - 完整 25 项套件：本地实跑 + 独立工作流 `e2e.yml`（workflow_dispatch + 每日定时），不随 push 常规执行。
- 凭据安全：测试栈密码/密钥均为一次性隔离环境凭据（栈销毁即失效），通过环境变量注入，trace/截图/报告中不打印。
